# 簡体字検査ツール `check_simplified_chinese.py` の記録

このファイルは新規ツール `training/tools/check_simplified_chinese.py` の実装内容、
実データの検出結果、テスト結果、CIでの使い方を記録する説明文書である。
既存の raw データ・学習成果物・検証ツール・LoRA・Kaggle Notebook は変更していない。

## 1. 実装の概要

| 項目 | 内容 |
|---|---|
| ファイル | `training/tools/check_simplified_chinese.py`（新規） |
| 既定の走査対象 | `training/raw/` を `Path.rglob("*.jsonl")` で再帰的に走査（37ファイル） |
| 検査文字数 | 130文字（`SIMPLIFIED_ONLY` と文脈ホワイトリスト対象の和集合） |
| 読み取り | ファイルを `open(..., encoding="utf-8")` で読むだけ。**書き込み処理は存在しない** |
| 報告内容 | ファイル名・行番号・列番号・該当文字・前後24文字の文脈・推奨置換字 |
| 集計 | ファイル別・文字別の件数、合計件数 |
| 出力 | 人間向けテキスト（既定）／`--json` で JSON／`--json --out FILE` で JSON ファイル |
| 上書き防止 | `--out` で既存ファイルを指定すると終了コード2で拒否する |

### 検出対象文字の考え方

`SIMPLIFIED_ONLY` には、日本語としては通常使わない簡体字の形のみを列挙している。
今回の課題である **`误` / `录` / `采` はいずれも必ず検出対象に含まれる**。

日本語として正しい漢字（`来`, `近`, `里`, `与`, `図`, `実`, `芸`, `国`, `車`,
`確`, `認`, `調`, `査`, `採`, `場`, `静` など）は意図的にリストから除外している。
実走査の初回で `装飾` / `装備` の `装` を誤検出したため、`装` を除外し、
あわせて `双`（双眼）と `践`（実践）も誤検出防止のため対象外にした。

### ホワイトリスト（文脈による誤検出防止）

`采` は簡体字の `採` として検出したい文字だが、日本語の `采配`（さいはい）と
`采女`（うねめ）は正しい語である。そのため `CONTEXT_WHITELIST` で次を定義し、
該当文字の前後がこれらの語の一部である場合は検出しない。

```
CONTEXT_WHITELIST = {"采": ("采配", "采女")}
```

`is_finding()` が行単位で文脈を確認し、ホワイトリスト語に一致した場合は除外する。
これにより `采用` / `采り` は検出し、`采配` / `采女` は検出しない。

## 2. 実データの検出結果（8件）

`training/raw/` 配下37ファイルを走査した結果、**8件**を検出した。

| ファイル | 行 | 文字 | 件数 | 推奨置換 | 文脈例 |
|---|---:|---|---:|---|---|
| `trpg_gm/gm_f_01.jsonl` | 3 | `误` | 1 | `誤` | `误りだったと分かった今、…` |
| `trpg_gm/gm_f_01.jsonl` | 3 | `录` | 1 | `録` | `彼女は記录板をこちらへ差し出した。` |
| `world_json/world_03.jsonl` | 3 | `采` | 6 | `採` | `采掘組`, `采掘組の男クロ` など |

- ファイル別: `gm_f_01.jsonl` 2件 / `world_03.jsonl` 6件
- 文字別: `采` 6件 / `误` 1件 / `录` 1件
- いずれも1行目ではなく **3行目**（JSONLの1レコード目）に集中している。

### 「文字数」と「行数」の集計単位の違い（重要）

このツールは**出現回数（文字数）**で数える。一方、
`training/tools/check_protected_text.py scan` は**行単位**で「その行に簡体字が presence するか」を数える。

| 集計単位 | 結果 | 理由 |
|---|---:|---|
| 出現回数（本ツール） | **8件** | `采` が `world_03.jsonl` の3行目に6回出現するので6件として数える |
| 行数（`check_protected_text.py scan`） | **3件** | `误` のある行、`录` のある行、`采` のある行の3行として数える |

数値が違うのは集計単位の違いであり、検出漏れや矛盾ではない。
「何箇所直す必要があるか」を見るなら出現回数（8件）、
「どの行をレビューすればよいか」を見るなら行数（3行）を使う。

## 4. CI での終了コード

| 終了コード | 意味 | CI での扱い |
|---:|---|---|
| 0 | 検出なし | 検査通過 |
| 1 | 簡体字を1件以上検出 | 検査失敗。レポートを確認して修正対象を特定する |
| 2 | 実行時エラー（`--out` の既存ファイル指定など） | 検査そのものの失敗として扱う |

使用例:

```bash
# 標準: raw 全体を走査（検出があれば終了コード1）
python3 training/tools/check_simplified_chinese.py

# JSON レポートを保存しつつ、検出があれば CI を失敗させる
python3 training/tools/check_simplified_chinese.py --json --out report.json

# 検出を警告扱いにしたい場合（失敗させない）
python3 training/tools/check_simplified_chinese.py || true
```

`--out` は既存ファイルを上書きしない（終了コード2）。CI では毎回新しいファイル名を指定するか、
保存先を事前に削除してから実行する。

**現在の実データには8件の検出があるため、このコマンドは現状終了コード1を返す。**
これは既知の未解決課題（別途記録済み）であり、今回は修正していない。
